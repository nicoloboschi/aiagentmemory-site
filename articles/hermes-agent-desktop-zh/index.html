Hermes Agent Desktop：安装、记忆与设置

October 24, 2026 2 min read
Hermes AgentNous Researchagent memory

Hermes Agent Desktop 是 Nous Research 为 Hermes 做的原生应用。介绍如何安装、它怎样和命令行共享记忆与会话、Memory Graph 功能以及限制。

Hermes Agent Desktop 是 Nous Research 的 Hermes Agent 官方原生应用，支持 macOS（Apple Silicon）、Windows 和 Linux。它不是另一个 Agent：底层运行的是和 hermes 命令行相同的核心，读取的是同一套配置、会话、技能和记忆。你可以从 Hermes 官网安装，如果已经装了命令行，也可以直接运行 hermes desktop。

Hermes Agent 使用 MIT 许可证，2026 年 10 月 24 日在 GitHub 上约有 256,500 颗星。下面的内容都来自官方的 Hermes Desktop 文档 和 安装指南，2026 年 10 月核对，当时 Hermes 版本为 v0.22.5。

什么是 Hermes Agent Desktop？

Hermes Agent Desktop 是一个 Electron 应用，在标准 Hermes Agent 运行时之上提供一个以聊天为主的窗口。 用 Nous Research 的话说，它使用的是“与命令行相同的配置、相同的 API 密钥、相同的会话、相同的技能、相同的记忆”，并且“不是一个单独的产品，也不是轻量克隆”。

Nous Research 于 2026 年 6 月 2 日以 v0.15.2 公开预览版的形式发布了它，Decrypt 报道过此事。应用默认会启动并管理自己的本地后端。它也可以连接到另一台机器上的 Hermes 后端（比如 VPS、家用服务器，或者通过 Tailscale 连接的 Mac mini），前提是那台机器上已经运行了 hermes serve。应用不会替你启动它。

如何安装 Hermes Agent Desktop

按照安装指南和 install.sh 脚本，有三种方式：

  1. 安装包。 从 Hermes 官网下载：macOS 上是 DMG（仅 Apple Silicon），Windows 上是 .appinstaller。
  2. 在已有的命令行安装上。 运行 hermes desktop。它会安装 Node 依赖，为你的系统构建 Electron 应用，然后启动。第一次运行时会从 GitHub 下载 Electron（约 114 MB）；如果网络被屏蔽，请设置 ELECTRON_MIRROR。
  3. 作为全新安装的一部分。 给安装脚本加上桌面参数：
1# macOS / Linux / WSL2
2curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --include-desktop

在原生 Windows 上，PowerShell 安装脚本（iex (irm https://hermes-agent.nousresearch.com/install.ps1)）接受 -IncludeDesktop 参数。

如果用 Ollama，ollama launch hermes-desktop 会在缺少 Hermes 时先安装它，让你选一个模型，把 Hermes Desktop 指向该模型，然后打开应用（Ollama 文档）。加上 --model <model> 可以跳过选择模型的步骤。

hermes desktop 常用的参数：

参数作用
--skip-build直接启动已经构建好的应用
--force-build即使没有变化也重新构建
--build-only只构建不启动（hermes update 会用到）
--cwd PATH在指定的项目目录中打开
--ignore-existing不启动本地后端

要卸载它，hermes uninstall --gui 只删除应用，hermes uninstall 删除应用和 Agent 但保留你的数据，hermes uninstall --full 全部删除。加上 --dry-run 可以先预览。

Hermes Desktop 如何使用记忆

应用使用的运行目录和命令行安装相同：~/.hermes，Windows 上是 %LOCALAPPDATA%\hermes，结构也一样。所以它的记忆就是 Hermes 的普通记忆：MEMORY.md（2,200 个字符的 Agent 笔记）和 USER.md（1,375 个字符的用户资料），会在会话开始时作为固定快照加载进提示词；过去的会话保存在 SQLite 中，Agent 需要时再搜索。完整的机制、限制和修复方法见 Hermes Agent 记忆。

应用额外提供的，是一种查看这些记忆的方式：

  • Memory Graph。 一个可缩放的节点图，展示 Hermes 学到的技能和记忆，可以按 All、Used 和 Learned 筛选，还带时间线。可以从命令面板或状态栏打开。它的分享按钮会把布局导出为一段代码；文档说，这段代码不包含任何记忆或技能的文字。
  • Learning Journey。 /journey（也可以用 /learning 或 /memory-graph）会按时间回放学到的技能和记忆。你可以在这里编辑或删除节点：删除技能会把它归档，删除记忆则会直接移除。
  • Memory & Context 设置。 和 Model、Workspace、Safety、Tools & Keys 并列的一个设置页，背后是配置文件。如果有两个或更多配置档案，“Applies to”选择器会决定你正在编辑哪个档案的 config.yaml。每个档案都有自己的配置、技能和会话。

由于共用同一份状态，会产生两个结果。在桌面聊天中写入的记忆，下一次终端会话里也能看到，反过来同样成立。另外，固定快照的规则仍然适用：在聊天中途保存的事实，要到下一次会话才会出现在提示词里，所以想让它生效，请新开一个聊天。

添加外部记忆提供商

桌面文档没有介绍记忆提供商。因为应用读取的是和命令行相同的 config.yaml 和插件，所以你在终端里配置的提供商，应用也会使用：

1hermes plugins install hindsight   # 也可以是 honcho、mem0、supermemory 或 openviking
2hermes memory setup                # 选择提供商，填入凭据
3hermes memory status               # 检查当前启用的是哪一个

除了 MEMORY.md 和 USER.md 之外，同一时间只运行一个外部提供商。Hermes Agent 插件页面介绍了它们如何安装和更新。

Hindsight 是列出的提供商之一，适合你会长期使用的桌面 Agent。在 Mem0 自己的对比页面上，Hindsight 在长历史的 BEAM 测试中领先：在 1M tokens 时是 73.9 对 64.1，在 10M tokens 时是 64.1 对 48.6（这些是厂商自己跑出的数字，不是独立测试）。在 LongMemEval 上两者持平（94.6 对 94.4）。Hindsight 使用 MIT 许可证，自托管服务器包含全部功能；它的 Hermes 插件有一个 local_embedded 模式，会运行带内置 Postgres 的本地守护进程，所以记忆留在你的机器上。通过 bank_id_template，你可以为每个 Hermes 档案分配独立的记忆库。限制也要说清楚：每次写入都会调用一次 LLM；插件默认每轮最多注入 4,096 个 tokens 的回忆内容（recall_max_tokens），每条消息都要为此付费。如果内置文件已经够用，就不必接入提供商。关于取舍的详细说明，见 Mem0 vs Hindsight。

已知限制

桌面文档列出了以下几点：

  • 桌面插件没有沙箱。 $HERMES_HOME/desktop-plugins/ 中的任何东西都以应用的全部权限运行，所以只安装你信任的插件。记忆本身也是一个攻击面，见 AI 记忆注入。
  • 在聊天中途切换模型会重置提示词缓存，所以下一轮会更贵。
  • 检查更新受速率限制：没有令牌时，每小时最多 60 次 GitHub 请求；设置 GITHUB_TOKEN 或用 gh 登录后可达 5,000 次。
  • Wayland 的特殊问题：在一些原生 Wayland 合成器上，窗口置顶和吸附到指针的功能无法使用。
  • macOS 版本只支持 Apple Silicon。

日志保存在 ~/.hermes/logs/desktop.log；hermes logs gui -f 可以实时跟踪。关于 Hermes 与 OpenClaw 在记忆上的比较，见 OpenClaw vs Hermes Agent 记忆。
