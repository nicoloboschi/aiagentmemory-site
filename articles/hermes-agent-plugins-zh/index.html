Hermes Agent 插件：安装、目录与记忆提供方

October 21, 2026 7 min read
Hermes AgentNous Research插件记忆提供方

Hermes Agent 插件如何工作：插件类型、hermes plugins install、固定 SHA 的目录、记忆提供方插件，以及 v0.23.0（2026 年 11 月）的变化。

Hermes Agent 插件是包含 plugin.yaml 清单的 Python 代码文件夹。它们可以添加工具、钩子、斜杠命令、记忆后端等功能，而不需要改动 Hermes 的核心。你可以用 hermes plugins install <名称> 从经人工审核、固定提交的目录中安装，也可以从任意 Git 仓库安装。记忆提供方插件比较特殊：同一时间只有一个在运行。

Hermes Agent 是 Nous Research 推出的开源（MIT）agent，截至 2026 年 10 月 21 日在 GitHub 上约有 256,000 颗星。本页介绍插件系统：插件类型、安装命令、目录、记忆提供方如何接入，以及有哪些提供方。Hermes 内置记忆如何工作（MEMORY.md、USER.md、会话搜索）见 Hermes Agent 记忆。事实来自 Hermes 插件文档 以及仓库中的 plugin-catalog/ 文件夹，2026 年 10 月 21 日核对。

什么是 Hermes Agent 插件？

Hermes 插件是一个目录，里面有 plugin.yaml 清单和一个定义了 register(ctx) 的 __init__.py。Hermes 启动时会调用这个函数，插件通过 ctx 注册模型可以调用的工具、生命周期钩子、斜杠命令、CLI 子命令、随附的技能，或者像记忆存储这样的后端。

用户插件放在 ~/.hermes/plugins/<名称>/。Hermes 还会在仓库的 plugins/ 文件夹中发现内置插件、暴露 hermes_agent.plugins 入口点的 pip 包，以及 NixOS 模块配置中声明的插件。项目本地的 ./.hermes/plugins/ 文件夹不会被加载：文档说，运行每个会话的网关每个进程只发现一次插件，而不是每个工作目录发现一次。

第三方代码默认关闭。能发现插件，但在它的名称写入 ~/.hermes/config.yaml 的 plugins.enabled 之前，带有工具或钩子的插件不会加载。文档说这样能“防止第三方代码在你未明确同意的情况下运行”。

Hermes 插件的类型

Hermes 插件文档 列出了四种类型：

类型作用同时运行几个如何开启
通用插件添加工具、钩子、斜杠命令、CLI 命令、技能任意组合plugins.enabled / hermes plugins enable
记忆提供方在 MEMORY.md 和 USER.md 之外添加一个外部记忆存储一个config.yaml 中的 memory.provider
上下文引擎替换内置的上下文压缩器一个config.yaml 中的 context.engine
模型提供方声明一个推理后端（OpenRouter、Anthropic 等）可加载多个，你选一个--provider 或 config.yaml

在通用插件中，ctx 还有更多入口：网关平台（Discord、Telegram、IRC）、图像和视频生成后端、终端沙箱、computer-use 驱动、审批通道、TTS 和 STT 后端，以及借用用户当前模型的 ctx.llm.complete()。有些扩展根本不是 Python 插件：MCP 服务器在 config.yaml 的 mcp_servers 下声明，shell 钩子在 hooks: 下声明。

钩子是通用插件响应 agent 的主要方式。文档列出的钩子有 pre_tool_call、post_tool_call、pre_llm_call、post_llm_call、on_session_start、on_session_end 和 post_compaction。钩子回调如果阻塞超过 plugins.hook_callback_timeout（默认 30 秒），就会被放弃；超时的 pre_tool_call 会阻止这次工具调用。从 v0.22.6 起，pre_llm_call 钩子还能阻止整个回合（见下文）。

如何安装 Hermes Agent 插件

按文档，常用流程如下：

  1. 查找。 hermes plugins search <关键词> 按名称、描述和声明的工具搜索目录。hermes plugins browse 列出所有条目，hermes plugins info <名称> 显示单个条目。
  2. 安装。 hermes plugins install <名称> 会以审核过的提交克隆该条目的仓库。安装前，提示会先显示声明的工具、钩子和环境变量。
  3. 回答启用提示。 Hermes 会问 Enable 'name' now? [y/N]（默认是否）。脚本中可用 --enable 或 --no-enable。如果是记忆提供方，它会改问 Use 'name' as the memory provider now?。
  4. 需要时授予权限。 声明了特权能力（例如 tools.override）的插件会弹出一次性的同意提示。授权保存在 plugins.entries.<id>.granted_capabilities 下。没有终端时，权限保持未授予。Python 依赖有自己的同意步骤，--enable 也跳不过：拒绝或在非交互模式下安装依赖，会让插件保持已安装但未启用。根据发布说明，Hermes v0.22.4（2026 年 10 月 21 日发布）对不安装依赖的插件跳过了这一步。
  5. 重启或开启新会话。 在会话中运行 /plugins 查看已加载的内容，或运行 hermes plugins list 查看已启用、已禁用和未启用的状态。
  6. 有意识地更新。 hermes plugins update <名称> 会把目录安装的插件移到目录当前的固定版本；不带名称时（v0.22.3 起）会列出所有可更新的插件并询问 “Update all N?”（--yes 跳过询问）。hermes plugins check-updates 只报告，不更新。从 v0.22.6 起，需要更新 Hermes 才能使用的更新会被跳过，旧的固定版本保留。
  7. 移除。 hermes plugins remove <名称> 卸载插件，把它从 plugins.enabled 和 plugins.disabled 中删除，如果它是当前的记忆提供方，还会重置 memory.provider。

完整命令如下：

 1hermes plugins                          # 交互式开关界面
 2hermes plugins list                     # 所有插件及其状态
 3hermes plugins search memory            # 搜索目录
 4hermes plugins install <名称>           # 目录条目，使用固定的 SHA
 5hermes plugins install owner/repo       # 任意 Git 仓库（未审核）
 6hermes plugins install owner/repo --ref <40 位 SHA>   # 固定版本的自定义安装
 7hermes plugins enable <名称>
 8hermes plugins disable <名称>
 9hermes plugins update [<名称>]
10hermes plugins capabilities [<名称>]    # 声明的与已授予的
11hermes plugins remove <名称>

每次安装和更新都会先运行静态安全扫描。safe 结论直接安装，caution 会询问 Install anyway? [y/N]，dangerous 即使加 --force 也会被阻止。以审核固定版本进行的目录安装会跳过 caution 询问，因为审核者已经看过这些结果。配置位于 ~/.hermes/config.yaml 的 plugins: 下（enabled、disabled、clone_timeout_seconds、hook_callback_timeout、load_timeout_seconds）；安装来源记录在 ~/.hermes/plugins/.install-metadata.json。

Hermes 插件目录

目录是 hermes-agent 仓库中的一组 YAML 文件，每个插件一个，并发布为一个 JSON 数据源，客户端最多每六小时刷新一次。2026 年 10 月 21 日，在线数据源列出了 754 个条目，数据来自 Hermes 文档站的 plugin-catalog.json。按分类看，有 241 个工具、174 个桌面、67 个记忆、66 个模型、52 个通用、48 个自动化、42 个网络、41 个平台、21 个语音，另有两个未分类。

目录 README 中的规则，是让一个裸名称可以安全安装的原因：

  • 由人合并。 条目只能通过维护者审核的 PR 加入。没有自助注册表。
  • 精确的 SHA 固定。 每个条目固定一个完整的 40 位提交。新的固定版本就是一个新的已审核 PR。
  • 没有自我更新的代码，不在运行时修补 Hermes 核心，也没有审核者读不懂的编译二进制。
  • 声明的能力必须与 固定提交中注册的内容一致。
  • 移除名单。 被下架的插件列在 removed.yaml 中，安装器会按名称或仓库 URL 拒绝它们。

每个条目都有一个级别。official 表示由 Nous Research 维护，verified 表示 Nous 确认其来源是它所集成产品的公司，community 是其他所有条目。2026 年 10 月 21 日，记忆分类的 67 个条目全部是 community 级别，包括 Honcho、Mem0、Supermemory 和 Hindsight，尽管这些项目由各自的公司维护。所以级别无法区分记忆提供方之间的差别。

Hermes 也在把自己的功能从核心移到 official 插件中。在 v0.22.5（2026 年 10 月 22 日）中，hermes import-agent 和 OpenClaw 迁移变成了 agent-importers 插件，hermes mcp serve 也离开了核心。运行没有对应插件的旧命令时，Hermes 会打印安装命令（hermes plugins install agent-importers）。导入器是记忆从 OpenClaw、Claude Code、Codex CLI 或 Cursor 迁入的方式；OpenClaw 与 Hermes Agent 的记忆对比 说明了它对每个文件的处理。

文档直言目录不是什么：“Cataloged ≠ audited”（收录不等于审计）。审核只检查固定的提交和收录时声明的能力，不是安全审计。所以对于要交出凭据的插件，请阅读它的代码。不在目录中的裸名称会报错；owner/repo 安装会跳过目录，并显示未审核代码的警告。

Hermes v0.23.0 中插件的变化

Hermes v0.23.0（2026 年 11 月 5 日）是 v0.22.x 补丁之上的完整版本，因此下面的 v0.22.6 变化也包含在内。插件方面的变化来自发布说明和 PR 内容：

变化v0.23.0 中的情况来源
目录规模v0.23.0 标签时有 1,050 个条目（2026 年 10 月 21 日为 754）。按分类：389 个工具、225 个桌面、96 个模型、79 个记忆、65 个通用、62 个自动化、53 个平台、52 个网络、27 个语音、2 个未分类2026 年 11 月 6 日，我们对该标签上 plugin-catalog/*.yaml 的统计（不含 removed.yaml）
级别1,019 个 community、21 个 official、9 个 verified、1 个无级别。79 个记忆分类条目仍全部是 community，包括 Honcho、Mem0、Supermemory 和 Hindsight同一统计
全部更新hermes plugins update 不带名称时只询问一次，并更新全部；一个失败不影响其余。没有终端时，除非加 --yes，否则什么都不更新；加了 --yes 后，新能力保持未授予#141513
自动更新plugins.auto_apply（默认关闭），也可用 /plugins auto-update，并在桌面版和仪表板中有开关；目录安装的插件也会更新发布说明，#85794
新的插件 APIctx.post_message 向当前聊天发送一条消息，并能原地编辑它；ctx.side_question 让你允许的插件在一个回合后向会话自己的 agent 提一个文本问题（同一份记忆，完整对话）#141005、#143791
新的钩子post_compaction（每次压缩完成时触发一次，附带压缩前后的 token 估算）和 on_session_delete（删除、归档、清理；不保证恰好一次）#141017、#140995
不兼容的改名hermes mcp serve 改为 hermes mcp-serve；启动 Hermes 的 MCP 客户端必须修改参数，Hermes 不会自动改写发布说明

对记忆提供方来说，这两个钩子补上了下文 MemoryProvider 接口中的空缺。提供方原本已经有 on_pre_compress，现在还可以在压缩删除内容后重新注入，并在你删除会话时清理自己的副本。ctx.side_question 在允许之前值得仔细考虑：回答来自一个加载了你记忆的 agent，所以拥有这项授权的插件可以问到 agent 知道的任何内容。本周期目录中的新记忆提供方有 Mnemoverse、post-cortex、Membase、conxt、Inspeximus 和 nyx。

Hermes v0.22.6 中插件的变化

Hermes v0.22.6（2026 年 11 月 2 日）是一个补丁版本，汇总了数百个已合并的 PR；v0.23.0 后来对它做了完整记录。以下三项插件变化在 v0.22.6 标签中（已对照合并提交核对）：

变化之前v0.22.6 中PR
目录中的 requires_hermes 下限只显示；安装和更新可能固定到需要更新版 Hermes 的提交安装被拒绝，并提示“<插件> 需要 Hermes <版本>；当前是 <版本>”，同时给出适合你安装方式的更新命令。hermes plugins update 保留已安装的固定版本，并把插件列为“更新 Hermes 后可更新”。search 仍会显示它，并带有 needs Hermes 一行#143468
pre_llm_call 可以阻止回合插件或 shell 钩子只能添加上下文，不能停止回合返回 {"action": "block", "message": "..."}（shell 钩子：{"decision": "block", "reason": "..."}），回合会在任何模型调用之前结束，用户会看到该消息。存储的提示词会变成被扣留的占位符，因此压缩、session_search、后台复盘，以及记忆提供方的 on_session_end / on_pre_compress 都不会看到它#81434
hermes update 会关闭插件如果该插件是记忆提供方，memory.provider 会被清空，原有选择丢失保留 memory.provider，变更记录在 plugins.disabled_by_update 下；之后的更新在插件符合要求时会重新开启它。hermes memory status 和 hermes doctor 现在会说明插件已关闭，而不是显示“All checks passed”#144257

阻止指令对记忆很重要：数据防泄漏插件现在可以阻止包含密钥的提示词，使其既不会进入模型，也不会进入外部记忆存储，而不只是阻止当前这一轮的回复。该 PR 用真实插件做的测试显示，被阻止的回合发出了 0 次 API 调用。

记忆提供方插件如何接入

记忆提供方插件继承 agent/memory_provider.py 中的 MemoryProvider，并通过 ctx.register_memory_provider() 注册。 它与内置的 MEMORY.md 和 USER.md 并行运行，从不取代它们。同一时间只有一个处于激活状态，由 memory.provider 选择；开发者指南说，第二次注册会被拒绝并给出警告。记忆提供方页面 说明了激活后提供方的作用。

提供方激活后，Hermes 会把它的上下文注入系统提示词，在每个回合前预取记忆，在回复后同步每个回合，在支持的情况下于会话结束时提取记忆，把内置记忆的写入同步到它那里，并添加提供方自己的工具。提供方开发者指南 列出了每一步背后的方法：

方法Hermes 何时调用是否必需
name、is_available()、initialize(session_id, **kwargs)启动时；is_available() 不得发起网络调用是
get_tool_schemas()、handle_tool_call()注入工具时，以及 agent 使用工具时是（有工具则需要处理函数）
get_config_schema()、save_config()hermes memory setup是（除非仅用环境变量，则需保存）
system_prompt_block()组装系统提示词时可选
prefetch(query)每次 API 调用之前；返回召回的上下文可选
queue_prefetch(query)每个回合之后，为下一轮预热可选
sync_turn(user, assistant)每个完成的回合之后；不得阻塞可选
on_session_end(messages)对话结束可选
on_pre_compress(messages)上下文压缩之前可选
on_memory_write(action, target, content)内置 MEMORY.md / USER.md 的写入可选
shutdown()进程退出可选

有两个细节容易出错。第一，hermes plugins enable <提供方> 不会激活记忆提供方；只有 memory.provider 才能激活，而 hermes memory setup 会写入它。第二，记忆提供方处理名称冲突的方式与通用插件相反：内置的那个优先，所以自制提供方需要一个唯一的名称。Hermes 交给提供方的所有内容，都会先经过与聊天输出相同的密钥清理，因此工具输出中回显的密钥在提供方保存之前就已被遮蔽。

Hindsight 适合的位置

Hindsight 是 Vectorize 推出的开源记忆服务器，采用 MIT 许可，自托管版包含全部功能。用 hermes plugins install hindsight 安装，由 Vectorize 在自己的仓库中维护；旧的 hindsight-hermes pip 插件已弃用。它提供三个工具（hindsight_retain、hindsight_recall、hindsight_reflect），三种模式（Hindsight Cloud、带内嵌 Postgres 的本地守护进程（空闲 5 分钟后停止），或你自己的 Hindsight 服务器），以及三种 memory_mode 设置：hybrid（自动上下文加工具，默认）、context 或 tools。

上述提供方中，只有 Hindsight 和 Mem0 有公开的正面对比数据。在 Mem0 自己的对比页面上（2026 年 10 月核对），Hindsight 与 Mem0 在 LongMemEval（94.6 对 94.4）和 LoCoMo（92 对 92.5）上基本持平。同一页面上，在长历史测试 BEAM 1M 中，Hindsight 得 73.9，Mem0 得 64.1。同一页面上，在 BEAM 10M 中，Hindsight 得 64.1，Mem0 得 48.6。以上都是厂商自行运行的结果，不是独立审计。

这对 Hermes agent 意味着什么：

  • 长时间运行的 agent。 在 Telegram 或 Discord 上运行的 Hermes agent 可以连续跑几个月。与之最相关的数据，是 BEAM 1M 和 10M 上的差距。
  • 会学习，而不只是存储。 Hindsight 把事实整合为 observations（带引文和证明次数的、有证据支撑的信念）和 mental models，reflect 返回的是经过推理的答案，而不是原始片段。
  • 需要时可以完全本地运行。 Hindsight 支持 25 个以上的 LLM 提供方，包括 Ollama、LM Studio 和 llama.cpp，因此内嵌模式可以把记忆留在机器上。

需要注意的限制。Hindsight 服务器在默认设置下，每次召回返回的上下文比 Mem0 多：按 Mem0 的测量，是 24K 到 44K token，对比 Mem0 的不到 7K。Hermes 插件对此做了限制：默认每回合召回上限为 4,096 token（recall_max_tokens），并且除非你把 recall_types 设为包含原始事实，否则只返回已整合的 observations。这是 Hindsight 的 Hermes 集成文档（2026 年 10 月）的说明。Hermes 每个回合都会预取召回，所以如果在意提示词成本，请调低 recall_max_tokens。每次保存和整合都会调用一次 LLM，所以写入比 Holographic 这种纯 FTS 存储更贵。它的目录条目和其他记忆条目一样是 community 级别；在云模式下，每个回合都会发送到 Hindsight 的 API，目录披露中也有说明。更多内容见 Mem0 与 Hindsight 对比 和 Hindsight 详解。

如何编写 Hermes 插件

通用插件只需要两个文件。以下是文档中最小的示例，钩子按照 钩子参考 中的 post_tool_call 签名编写（Hermes 会把钩子的字段作为关键字参数传入）。

~/.hermes/plugins/hello-world/plugin.yaml：

1name: hello-world
2version: "1.0"
3description: A minimal example plugin

~/.hermes/plugins/hello-world/__init__.py：

 1import json
 2
 3
 4def register(ctx):
 5    schema = {
 6        "name": "hello_world",
 7        "description": "Returns a friendly greeting for the given name.",
 8        "parameters": {
 9            "type": "object",
10            "properties": {"name": {"type": "string", "description": "Name to greet"}},
11            "required": ["name"],
12        },
13    }
14
15    def handle_hello(params, **kwargs):
16        name = params.get("name", "World")
17        return json.dumps({"success": True, "greeting": f"Hello, {name}!"})
18
19    ctx.register_tool(name="hello_world", toolset="hello_world",
20                      schema=schema, handler=handle_hello)
21
22    def on_tool_call(tool_name, **kwargs):
23        print(f"[hello-world] tool called: {tool_name}")
24
25    ctx.register_hook("post_tool_call", on_tool_call)

然后运行 hermes plugins enable hello-world，并开启新会话。模型看到的是 schema["description"] 中的文字，所以工具的说明要写在那里。

记忆提供方遵循相同的 register(ctx) 模式。下面是开发者指南中的骨架：

 1from agent.memory_provider import MemoryProvider
 2from agent.secret_scope import get_secret
 3
 4
 5class MyMemoryProvider(MemoryProvider):
 6    @property
 7    def name(self) -> str:
 8        return "my-provider"
 9
10    def is_available(self) -> bool:
11        return bool(get_secret("MY_API_KEY"))  # 这里不要发起网络调用
12
13    def initialize(self, session_id: str, **kwargs) -> None:
14        self._session_id = session_id
15        self._home = kwargs.get("hermes_home")
16
17    def get_tool_schemas(self):
18        return []
19
20    def prefetch(self, query: str, *, session_id: str = "") -> str:
21        return ""  # 本回合召回的上下文
22
23
24def register(ctx) -> None:
25    ctx.register_memory_provider(MyMemoryProvider())

用 get_secret() 读取密钥，不要用 os.environ，这样每个 Hermes 配置档都有自己的密钥。慢的工作放在 sync_turn() 中，并通过 agent.memory_provider.spawn_context_thread 启动线程，因为文档说，普通线程可能会把数据写入错误配置档的存储。要把插件加入目录，请提交一个 PR，新增一个带精确 SHA 的 plugin-catalog/<名称>.yaml，并遵循提交指南。由于被注入提示词的记忆是一条真实的攻击路径，在发布会存储不可信聊天内容的提供方之前，请先阅读 AI 记忆注入。
