Open Source AI Memory Systems Compared: GitHub Repos

March 24, 2026 11 min read
Open SourceAI Agent MemoryLLM MemoryGitHub

Open-source AI memory systems compared: GitHub repos, licenses, stars (Oct 2026), languages and what each is good at. Mem0, Hindsight, MemPalace, Graphiti, Cognee.

The leading open-source AI agent memory systems on GitHub are Mem0, MemPalace, Hindsight, Graphiti, Cognee, Letta, LangMem, MemOS, Memori, Honcho, Basic Memory and Memobase. Most are Apache-2.0 or MIT, written in Python, and self-hostable with Docker. They differ in storage (vectors, graphs, files), in how much is truly open versus paid, and in what they’re built for.

If you want the most complete fully open option, it’s Hindsight: its MIT server includes graph and temporal recall, consolidation and reflect, which Mem0 keeps on its paid Platform, and it leads Mem0 on the long-history BEAM benchmark by 9.8 points at 1M tokens and 15.5 at 10M (vendor-run). This page covers only open-source projects: repos, licenses, stars, languages and strengths. Star counts, licenses and last-push dates come from the GitHub API on 18 October 2026. For hosted options and benchmarks, see the LLM memory comparison. For background, see AI agent memory explained.

What is an open-source AI memory system?

An open-source AI memory system is a library or server, published under an open license, that stores what an LLM agent learns from conversations and work, then retrieves relevant memories into later prompts. You can read the code, run it on your own infrastructure, and keep memory data under your control. Most also offer a paid hosted version.

How open is “open source”? Read the fine print

Several projects are open core: the repo is open, but some features or the best-performing version are paid. Check these before you build on one.

  • Mem0: graph memory was removed from the open-source SDK in v3 and “is not being replaced by an OSS equivalent.” Mem0 also says its April 2026 benchmark scores come from the managed platform with “proprietary optimizations not available in the open-source SDK.”
  • Zep: Zep Community Edition is deprecated and moved to a legacy/ folder. Graphiti is the open-source part; Zep itself is a managed service.
  • Supermemory: the repo is MIT, but its self-hosting docs say the local server’s “source is not in the public repository.” It’s a free binary under a “lite license,” not code you can build.
  • Cognee: the core is Apache-2.0, but running the graph store on Postgres is a demo; “the production-ready version is available as a licensed product.”
  • Letta: the Letta V1 API server is retired to an archive branch. Current development is the Letta Code harness, which defaults to Letta Cloud but has a local backend.
  • Hindsight: MIT, with no open-core split: graph, temporal recall, consolidation, reflect and mental models are all in the open-source server. Its pricing page lists self-hosting as free with no usage limits. The paid part is the managed cloud.
  • AGPL projects (Honcho, Basic Memory): free to self-host, but if you modify them and offer them as a network service, AGPL-3.0 requires you to publish your changes. Many companies’ legal teams treat AGPL differently from MIT or Apache.
  • Source-available, not open source: aoci-code (1,602 stars) keeps a Git-versioned map of a codebase and database schema for coding agents to read, and is often listed with the projects above. Its licence is the Functional Source License 1.1 with an MIT future grant, so you may read and use the code but not compete with it until the grant converts two years after each release. That is a different thing from the MIT and Apache repos in the table, and it is worth knowing before you build a product on it.

What each open-source memory system is built for

Mem0

Extracts facts from conversations and stores them per user, session or agent. Runs as a library (local Qdrant and SQLite by default), a Docker server (Postgres + pgvector), or Mem0’s cloud. Hybrid BM25 and entity search need the [nlp] extra. Good first choice for chat personalization. More in what is Mem0 and Mem0 alternatives.

Hindsight

Built by Vectorize. Organizes memory into world facts, the agent’s experiences, consolidated observations and mental models, with retain, recall and reflect operations. Recall runs semantic, BM25, graph and temporal search in parallel. Ships as Docker, pip, Helm or an embedded Python package, with clients for Python, Node.js, Go and a CLI, and a built-in MCP endpoint per bank. It works with 25+ LLM providers, local ones included, and has 60+ integrations, among them native plugins for Claude Code, Codex, Cursor and Copilot. Described in the paper Hindsight is 20/20.

Its strongest case is long histories: on BEAM it scores 73.9 at 1M tokens and 64.1 at 10M, against Mem0’s 64.1 and 48.6, numbers that Mem0’s own comparison page lists. On LongMemEval it reports 94.6. The costs: it returns about 4x more context per retrieval than Mem0 by Mem0’s measurement (you set max_tokens), writes call an LLM twice (retain and consolidation), and its README says it may be overkill for simple workflows. See Mem0 vs Hindsight.

MemPalace

Stores conversations and project files verbatim, sorted into wings and rooms, and searches them locally with BM25 and vectors over ChromaDB. No LLM or API key needed. Ships auto-save hooks for Claude Code, Codex CLI and Cursor. Its LongMemEval figure (96.6% recall@5) is retrieval recall, not answer accuracy. See MemPalace and Mem0 vs MemPalace.

Graphiti

Builds temporal knowledge graphs: entities, facts with validity windows, and the raw episodes they came from. Old facts are invalidated, not deleted, so you can query past states. Needs a graph database (Neo4j, FalkorDB or Amazon Neptune; Kuzu support is deprecated). Includes an MCP server. See Zep alternatives and knowledge graphs for AI memory.

Cognee

Turns text, code and conversations into a graph plus vector index, with file-based defaults (SQLite, LanceDB, LadybugDB) so it runs with no setup. Version 1.6.0 (September 2026) added keyless workflows using local models. It has plugins for Claude Code, Codex and OpenClaw. See Mem0 vs Cognee and Cognee alternatives.

Supermemory

The main repo is TypeScript and MIT licensed, and its plugins for Claude Code, Cursor, Codex, OpenCode and OpenClaw are separate open-source repos. The memory engine you self-host is the free local binary noted above, not code from the repo. See Supermemory explained.

Letta

From the authors of MemGPT. Letta Code agents keep memory in MemFS, a git-backed filesystem, and rewrite their own memory, skills and prompts. Best when you want the whole agent runtime, not just a memory layer. See Letta alternatives.

LangMem

Memory tools an agent calls during a conversation, plus a background manager that extracts and consolidates memories, on top of LangGraph’s store. Least effort if you already run LangGraph. See LLM memory with LangChain.

Smaller and specialized projects

  • Honcho: peer-centric memory with background reasoning, on Postgres + pgvector. See Honcho LLM memory.
  • MemOS: memory cubes, async ingestion, local SQLite plugins for OpenClaw and Hermes Agent.
  • Memori: stores agent state in your own database (“BYODB”); its older home was GibsonAI. See Memori by GibsonAI.
  • Basic Memory: plain markdown files plus a local SQLite index, exposed over MCP.
  • Mnemosyne: everything lives in one SQLite file, searched with sqlite-vec for vectors and FTS5 for keywords, in three tiers: working memory that is injected before the LLM call and expires, episodic memory for the long term, and a temporal triple store with version chains. Ships an MCP server, a native OpenClaw provider and a Hermes Agent plugin that is on by default. Its sync between your own machines encrypts content client-side, so the remote server sees only event IDs, timestamps and device IDs. It is also unusually careful with its own numbers: it withdrew a 98.9% LongMemEval figure in September 2026 because no methodology or run log for it existed, and labels its BEAM scores as measured on v3.0.0 (May 2026) and not re-run since. A side-by-side with the system its README ranks above it is in Mnemosyne vs Hindsight.
  • Memobase: a profile and event timeline per user, built on FastAPI, Postgres and Redis. No commits since January 2026.
  • agent-memory (tigerless-labs): markdown files are the store and the SQLite index beside them is a cache you can delete and rebuild. Recall answers with file paths and one-line abstracts rather than pasted text, so the agent opens only what it needs, and a background pass consolidates while deletions wait for your confirmation. No API key, and the store stays greppable and git-able.
  • Leviathan: a single Rust binary that indexes JSONL, CSV, SQLite or any database CLI’s output for full-text search, so an agent asks in plain words instead of grepping. Its README reports a median 436 tokens per answer at 1M records on one synthetic maintenance log, which is a vendor benchmark on a dataset of its own making. Closer to agent-facing search than to memory that is written as the agent works.
  • OKF Agent Memory: keeps project knowledge as Google’s Open Knowledge Format files inside the repo, with a capped AGENTS.md for rules that must always load and on-demand BM25 search for everything else. Go, no dependencies, MCP server included.

What is an LLM memory bank?

A memory bank is an isolated store of memories for one user, agent or project. The idea goes back to MemoryBank (Zhong et al., 2023), which added long-term memory to chatbots and used a forgetting mechanism inspired by the Ebbinghaus forgetting curve. Today the word shows up in three places:

  • Hindsight calls each isolated store a bank, with strict isolation between banks.
  • Google’s Vertex AI Agent Engine has a managed Memory Bank; see Vertex AI Agent Engine Memory Bank.
  • Coding-agent “memory bank” setups keep project notes in markdown files that the agent reads at the start of each session.

People searching GitHub for “awesome LLM memory” lists will find several, but as of October 2026 the ones we checked were small (under 10 stars). The repos in the table above are a better starting point.

How to try an open-source memory system in ten minutes

Cognee’s quickstart runs fully local, with no API key:

 1# pip install "cognee[gliner]"
 2import asyncio
 3import cognee
 4
 5async def main():
 6    # Extracts a small graph and embeds the text with local models
 7    await cognee.remember(
 8        "Marie Curie was born in Warsaw and worked at the University of Paris.",
 9        dataset_name="local_quickstart",
10    )
11    results = await cognee.recall(
12        "Where was Marie Curie born?",
13        datasets=["local_quickstart"],
14    )
15    for result in results:
16        print(result)
17
18asyncio.run(main())

To pick a repo for production, run through this list:

  1. Check the license against how you’ll ship (internal tool, SaaS, on-prem product).
  2. Check what’s gated: read the pricing page for features that are cloud-only.
  3. Check activity: recent commits, open issues and release notes in the last 90 days.
  4. Check dependencies: Postgres only, or also a graph DB, Redis and a vector DB?
  5. Check the LLM cost per write: most systems call an LLM on every memory add.
  6. Run your own test: 20-50 real questions on your data, with two candidates.
