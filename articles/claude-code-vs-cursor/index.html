Claude Code vs Cursor on memory: CLAUDE.md and auto memory vs .cursor/rules and AGENTS.md, what loads each session, and where Hindsight fits for both.

Claude Code vs Cursor: which one remembers more?

Both tools read instruction files at the start of a session, so both can carry project rules across chats. The difference is who writes the memory. Claude Code can save its own notes (auto memory) on top of the files you write. Cursor’s documented memory is the rules you write: project rules, AGENTS.md and user rules. Cursor’s rules page says large language models do not keep memory between completions, so rules are what persist.

What Claude Code remembers on its own

Claude Code has two memory systems that load every session. CLAUDE.md is written by you: coding standards, workflows and project architecture. Auto memory is written by Claude: your preferences, corrections you gave, and project facts it cannot get from the code.

Auto memory has four note types: user, feedback, project and reference. Claude skips anything it can read from the codebase or from a CLAUDE.md file. Only the first 200 lines or 25KB of MEMORY.md load at startup, so a long index loses its tail. Topic files load only when Claude opens them.

What Cursor remembers

Cursor’s memory is its rules. A project rule is a .mdc file in .cursor/rules with metadata that says when it applies: a path pattern, a manual call, or relevance. A plain .md file in that folder is ignored. Cursor says it applies rules in this order: Team Rules, then Project Rules, then User Rules, and merges all that match.

Cursor also reads AGENTS.md in the project root and in subdirectories. Nested files add to the parent files, and the more specific file wins when they conflict.

Where Hindsight fits

Hindsight is an open-source memory server (MIT license, full server in the open-source version). It adds a memory layer that the agent recalls from and writes to, on top of or in place of plain files.

  • One install for both tools: npx @vectorize-io/hindsight-coding-agents install claude-code sets up Claude Code. The same package covers 22 CLI agents, including Cursor CLI, and gives every agent one bank per repository (coding-agent::{gitProject}), so Claude Code and Cursor CLI share what they learn about a repo.
  • Capture is automatic: there is no setup command after install. Memory can live in Hindsight Cloud, a server you run, or a local daemon.
  • Where it does not fit: the Cursor IDE is not on the package’s list of 22 agents. Gemini CLI is not on it either. The old Claude Code plugin is retired and gets no updates, so use the package.
  • The limit: Hindsight is one more service to run or a cloud account to set up. A CLAUDE.md file or a .cursor/rules file needs neither. Our fact sheet has no benchmark for coding sessions, so this page makes no number claim for them.

If your rules are short and stable, plain files are enough. If the agent should learn from each session and share it across tools, add a memory layer. See AI coding agent memory for the options, and Claude Code memory and Cursor rules for the full file formats.

How to choose

Pick the tool you already use. Keep one instruction file that both tools read (AGENTS.md is read by both), and add the tool-specific file only for what differs. Claude’s docs call CLAUDE.md context, not enforced settings, so a rule that must always hold needs a check outside the prompt. For Claude Code, a hook can block an action outright.
